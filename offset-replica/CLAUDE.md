# Pixel-perfect replica: HTML + Tailwind CSS

## Goal
Recreate the website **exactly** as shown in the reference screenshots in `refs/`.
The screenshots are the single source of truth. Do not redesign, "improve",
modernise or reinterpret anything. If something looks odd in the screenshot,
replicate the oddity.

## Reference settings (EDIT THESE FIRST)
- Reference viewport width: **1672px** (CSS px); each sheet is 1672x941 (`refs/sheet-N.png`, copied from `../desgin_sheets/`)
- Screenshot device pixel ratio: **1**
- Fonts: sheets are AI-generated mockups, so no exact font exists. Best fit (tools/fontrank.mjs): Hanken Grotesk 300 for headline/subtitle, Geist for small labels, Jost for the OFFSET wordmark. Headline/subtitle use per-word left + tracking (tools/fitwords.mjs).
- Colours: sampled with `npm run sample` (nav/logo ~#152328/#181c1c, tag text #5a5e62/#384753).
- Layout: `index.html` is GENERATED by `python tools/gen-index.py` (edit the generator, then `npm run build:css`). Desktop >=1100px = the 1672x941 comp scaled with the viewport (root font-size = 100vw*16/1672, every `desk:` px value converted to rem). Below 1100px = mobile-first stacked layout (CSS-only menu via checkbox). Compare at 1672px must stay the same after any responsive change.

## Stack rules
- Plain HTML in `index.html` + Tailwind CSS v4. No frameworks, no JS unless the
  screenshot clearly shows interactivity that is required.
- Style only with Tailwind utilities. Use arbitrary values for exact numbers
  (`w-[372px]`, `text-[15px]`, `leading-[22px]`, `tracking-[-0.02em]`,
  `bg-[#0f172a]`). Custom CSS only when no utility can do it.
- Tailwind is compiled: after every HTML change run `npm run build:css`
  (or keep `npm run watch:css` running). `index.html` links `dist/output.css`.
- One `<section id="...">` per screenshot. The id equals the screenshot name,
  e.g. `refs/home-hero.png` -> `<section id="home-hero">`.
- Use semantic HTML (header, nav, main, section, footer, h1-h3, a, button).
- Images/icons that cannot be reproduced from a screenshot: use a neutral
  placeholder of the **exact same size** and tell me which assets you need.
  Never invent stock imagery.

## Workflow: ONE section at a time
For each screenshot, in the order I give you:
1. **Inspect** the reference image. Before writing code, list what you measure:
   section height, container width, paddings, gaps, font sizes / weights /
   line-heights, border radii, shadows, and the colour of every distinct element.
2. **Sample colours, don't eyeball them:**
   `npm run sample -- refs/<name>.png x,y x,y ...` prints exact hex values.
3. **Build** the section in `index.html`.
4. **Compare numerically:**
   `npm run compare -- --ref refs/<name>.png --selector "#<name>"`
   (add `--dpr 2` for retina references). It prints size, mismatch %, and the
   worst vertical bands, and writes `shots/<name>.png` and `diffs/<name>.diff.png`.
5. **Look at the result too.** Open `diffs/<name>.diff.png` and your shot, and/or
   screenshot the page with the Playwright MCP, then compare against the
   reference visually.
6. **Iterate** until: rendered size == reference size exactly, and mismatch <= 1%.
   Fix size first (height/width), then position, then typography, then colour.
7. **Stop and report** before starting the next section: final mismatch %,
   what still differs, and anything you had to assume (fonts, assets).

## Rules
- Never claim "pixel perfect" without running `npm run compare` and quoting the number.
- Do not touch a finished section while working on the next one, unless a
  shared value (font, colour token) must change; then re-run compare on all
  finished sections.
- When you cannot determine something from the image (exact font, image asset,
  hover behaviour), ask me instead of guessing silently.
- Desktop first. Responsive behaviour comes only after I ask for it.
- If the `frontend-design` skill is active: its "bold aesthetic direction"
  guidance does NOT apply here. Fidelity to the screenshot overrides it.
